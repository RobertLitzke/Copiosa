# The learning science behind Copiosa

Copiosa is a native Android app (Kotlin + Jetpack Compose) for adult second-language learners. It combines LLM-generated graded conversations and texts, an FSRS-scheduled flashcard system with full Anki interoperability, on-device translation and dictionary lookup, neural TTS audio playlists, and an adaptive bedtime practice routine. The user supplies their own LLM API key (Gemini or OpenRouter); everything else — scheduling, translation, dictionary, TTS — runs on-device and offline.

This document explains the **language-acquisition science the app is built on**: which concepts from second-language acquisition (SLA) research and cognitive psychology are implemented, how each maps to a concrete feature, and — just as importantly — which well-established concepts are *not yet* represented.

---

## Part 1 — Concepts implemented in the app

### 1. Memory and retention

#### 1.1 Spaced repetition and the spacing effect

The spacing effect — that memories are retained far better when reviews are distributed over expanding intervals rather than massed — is among the most replicated findings in cognitive psychology, going back to Ebbinghaus (1885) and quantified in modern meta-analyses (Cepeda et al., 2006).

The app schedules every flashcard with **FSRS** (Free Spaced Repetition Scheduler), the open-source algorithm that modern Anki uses. FSRS models each card with the three-component **DSR model of memory** — *Difficulty*, *Stability* (how long the memory lasts), and *Retrievability* (probability of recall right now) — and schedules the next review for the moment retrievability decays to a target retention (0.9 here). This is a meaningful upgrade over the older SM-2 family: instead of a single "ease factor," each card carries an explicit, empirically fitted memory state.

- Implementation: [SpacedRepetitionScheduler.kt](../app/src/main/java/com/copiosa/domain/srs/SpacedRepetitionScheduler.kt) delegates the memory math to the FSRS engine; cards persist `stability`, `difficulty`, state (new / learning / review / relearning), lapses, and interval.
- Every graded review is logged append-only in a review log (`ReviewLogEntity`) — the same data Anki keeps in `revlog` — which is the raw material for future per-learner parameter optimization (see Part 2).
- Cards imported from Anki with only SM-2 state are *seeded* into FSRS (interval ≈ stability at 0.9 retention) so their schedule continues rather than resetting — review history is treated as sacred.

#### 1.2 Retrieval practice (the testing effect)

Actively retrieving an answer strengthens memory far more than re-reading it (Roediger & Karpicke, 2006). The review flow is built around retrieval: the learner sees one side, commits to an answer mentally, reveals, then self-grades on the standard four-point scale (**Again / Hard / Good / Easy**). "Again"-graded cards are re-queued to the end of the same session, Anki-style, so a failed retrieval is retried while the session is still warm.

#### 1.3 Desirable difficulties

Bjork's "desirable difficulties" framework holds that conditions which make practice *feel* harder (retrieval instead of recognition, varied presentation, spacing) produce more durable learning. Several deliberate choices follow from it:

- **Bidirectional review**: cards can review target→native, native→target, or randomly **both** directions ([ReviewDirection](../app/src/main/java/com/copiosa/domain/model/Enums.kt)), forcing both recognition and (harder, more valuable) production-side recall rather than letting the learner settle into the easy direction.
- **Cloze deletion** ([Cloze.kt](../app/src/main/java/com/copiosa/domain/model/Cloze.kt)): Anki-compatible `{{c1::…}}` cards blank the target inside a full sentence, testing recall *in grammatical context* rather than as an isolated pair.
- Contrast-cloze answers are deliberately varied so neither option is correct every time — preventing pattern-learning shortcuts that would remove the difficulty (see §3.2).

#### 1.4 Dual coding

Paivio's dual-coding theory: information encoded both verbally and visually forms two mutually reinforcing memory traces. Vocabulary cards can carry an image (searched from Openverse, stored locally, shown during review and on the card detail page), and a dedicated stepping flow walks through imageless cards to attach pictures in bulk ([ImageSearchRepository.kt](../app/src/main/java/com/copiosa/data/repository/ImageSearchRepository.kt)). Card audio imported from Anki (or generated by TTS) adds a third, phonological trace.

#### 1.5 Incidental re-exposure as review ("passive review")

Repeated *encounters* with a word in meaningful input contribute to retention even without deliberate testing (Nation's "repeated meetings"; incidental vocabulary acquisition research, e.g. Hulstijn). When a saved word that is due within two weeks appears in a chat reply, an imported text, or a routine reading, the app treats the sighting as a light review and pushes its due date back (capped at 30 days / half the interval) — implemented in [ReadingSelectionController.kt](../app/src/main/java/com/copiosa/ui/components/ReadingSelectionController.kt). Deliberately, this does **not** write an FSRS review or a revlog entry: a sighting is weaker evidence than a graded retrieval, and keeping it out of the log keeps the Anki round-trip honest.

### 2. Input and acquisition

#### 2.1 Comprehensible input and i+1

Krashen's Input Hypothesis: acquisition happens when learners understand messages containing structures slightly beyond their current level ("i+1"). This is the app's central content principle:

- Every conversation is generated by a system prompt instructing the model to "deliver comprehensible input at approximately **{level}** level, with occasional **{next level}** vocabulary" — the learner's CEFR level plus a controlled sprinkle from one level up ([PromptBuilder.kt](../app/src/main/java/com/copiosa/domain/prompt/PromptBuilder.kt)).
- Imported web articles are not just translated — they are **graded**: "simplifying vocabulary and grammar to that level is the priority, but preserve the original's tone, voice, register and style." The learner reads real-world content of their own choosing, adapted downward to comprehensibility.
- The model always replies in the target language, even when the learner writes in their native language — maximizing input volume — with the single exception of explanations, which use the native language (comprehension of *meta*-talk matters more than immersion there).
- Level is a first-class, per-language setting (CEFR A1–C2), snapshotted onto every generated message so the input level of any past content is auditable.

#### 2.2 Narrow reading

Krashen's "narrow reading" argument: reading several texts in one topic area is more effective than scattered reading, because vocabulary and structures recur naturally and background knowledge compounds. The bedtime routine includes a **narrow reading** activity — a short, level-appropriate passage generated around a single familiar topic, recycling recently studied vocabulary — and the serial story (§4.2) extends the same principle across nights.

#### 2.3 Glossing and dictionary access during reading

On-demand glossing during reading supports incidental vocabulary acquisition without breaking flow (Hulstijn et al.). The reader implements a Kindle-style lookup ladder, cheapest first:

1. Tap/drag any word or phrase → instant **on-device translation** (ML Kit, offline after a one-time model download).
2. Single words also get an **offline dictionary** entry (Wiktionary-derived SQLite pack): part of speech, gloss senses, and **lemma resolution** — tapping a conjugated form like *vivió* surfaces the infinitive *vivir*.
3. Optionally escalate to an **LLM explanation** in context: a colloquial 2–4 sentence note covering nuance, register, close synonyms, plus a generated example sentence.
4. One tap saves the word as a flashcard — with the option to save the lemma rather than the surface form.

#### 2.4 Noticing and input enhancement

Schmidt's Noticing Hypothesis holds that input becomes intake only when features are consciously noticed; Sharwood Smith's "textual input enhancement" operationalizes this by making target forms visually salient. The app highlights saved words everywhere they appear in reading and chat ([WordColorizer.kt](../app/src/main/java/com/copiosa/ui/components/WordColorizer.kt)) — with three research-relevant refinements:

- Highlighting is **inflection-aware**: saving *gato* also highlights *gatos*; saving a verb highlights its conjugations (surface forms precomputed from the dictionary pack).
- For gendered nouns the **preceding article is tinted too** (*la fiesta*), drawing attention to gender agreement — a classically hard-to-notice feature for English speakers.
- Only words **due for review soon** (≤ 7 days) are highlighted; words that are locked in (due > 90 days) are not. Salience is spent where noticing still pays, and mastered words fade into normal text — the enhancement itself is spaced.

#### 2.5 Vocabulary recycling across contexts

Nation's vocabulary research suggests a word needs on the order of 8–12 meaningful encounters, ideally in varied contexts, to be learned. The app engineers those encounters:

- Every new conversation is seeded with ~10 of the learner's soonest-due saved words, drawn from a pool of the next 100 up for review, with the instruction to "use the ones that fit naturally … never force them." Batch-created chats receive **non-overlapping** vocab slices so ten conversations recycle a hundred distinct words.
- Routine activities (narrow reading, bedtime story, cloze drills) recycle recently studied words as their seed vocabulary.
- The model reports back which supplied words it actually used, so recycling is observable rather than assumed.

#### 2.6 Contextual learning and "sentence mining"

Words are stored with the **sentence they were encountered in**: saving from a chat or text captures the surrounding sentence as the card's context/example field, and the card links back to its source conversation. This mirrors the "sentence mining" practice from the immersion-learning community and the broader finding that context-bound encoding aids both retention and appropriate usage.

### 3. Form-focused instruction

#### 3.1 Processing Instruction (VanPatten)

Processing Instruction is one of the best-evidenced grammar-teaching techniques in SLA. Its insight: learners default to lexical cues (subject pronouns, time adverbs) and skip grammatical form entirely, so effective input must be *structured* to make the form the only path to meaning. The routine implements both canonical PI activity types:

- **Referential PI**: one fully conjugated, **pro-dropped** sentence whose verb form alone reveals who/when — the prompt explicitly forbids subject pronouns (*yo, tú, él…*) and time adverbs (*ayer, hoy, mañana*), and a structural validator ([RoutineValidation.kt](../app/src/main/java/com/copiosa/domain/routine/RoutineValidation.kt)) rejects generated items that leak those cues. The learner must parse *-ó* vs *-o* vs *-aba* to answer.
- **Affective PI**: "which statement is true for you?" — pre-conjugated statements with no right answer, giving low-pressure exposure to the same forms while engaging self-reference (which itself aids memory — the self-reference effect).

#### 3.2 Contrast-based discrimination

The hardest grammar points for a given L1→L2 pairing are typically *contrasts* the L1 doesn't make (for English→Spanish: ser/estar, por/para, preterite/imperfect, subjunctive/indicative). The **contrast cloze** activity drills exactly these: one blank, exactly two options forming the contrast pair, tracked per contrast category so adaptation (§5) can distinguish "comfortable with por/para" from "still shaky on subjunctive triggers." Item generation is constrained to vary which side is correct, so the drill measures discrimination, not answer-pattern memorization. A three-option **multiple-choice cloze** variant uses meaning-distinct distractors to test lexical discrimination rather than form contrast.

#### 3.3 Morphological awareness

Morphologically rich languages punish learners who treat words as unanalyzed strings. Morphology surfaces throughout:

- Lemmatization on save (offer the infinitive, not the conjugated surface form).
- Inflection-aware highlighting (§2.4).
- Cards carry part of speech, gender (with distinct handling for epicene and plural-only nouns), and regional/dialect tags, displayed as chips during review; gender chips are color-coded.
- The dictionary pack maps inflected forms back to lemmas with grammatical tags.

#### 3.4 Cognate awareness and false friends

For related language pairs, cognates are a massive free lexicon — and false friends are its tax. The **cognate hunt** activity presents a mixed set and has the learner classify true cognates vs false friends (*éxito* ≠ "exit"), training the discrimination explicitly rather than leaving it to painful discovery.

### 4. Affect, consolidation, and habit

#### 4.1 The affective filter

Krashen's Affective Filter Hypothesis: anxiety and low confidence block input from becoming acquisition. Several design decisions lower the filter:

- **Adaptation is silent.** Difficulty and activity selection adjust from performance (§5), but no score, streak, or grade is ever shown during practice. The optional "Comfort levels" screen reframes mastery data as *comfort* (Building / Comfortable / Mastered) — deliberately non-evaluative vocabulary.
- Affective PI has no wrong answers by construction.
- The bedtime routine's content is constrained to be calm and pleasant (a keyword-level **calm heuristic** biases topic selection toward soothing themes and away from agitating ones).
- Conversations are private, self-paced, and judgment-free — the standard argument for LLM conversation partners lowering speaking/writing anxiety relative to human interlocutors.

#### 4.2 Sleep-dependent memory consolidation

Newly encoded material is preferentially consolidated during subsequent sleep (Stickgold, Walker, and the targeted-memory-reactivation literature); studying shortly before sleep, followed by sleep, measurably improves retention relative to equivalent study followed by waking activity. The app's flagship routine is a **bedtime wind-down** engineered around this:

- A pre-sleep practice session reactivates recent vocabulary right before the consolidation window.
- The session follows a **monotonically de-escalating arousal arc** — Engage (~30%) → Settle (~40%) → Drift (~30%) — enforced by the planner ([RoutinePlanner.kt](../app/src/main/java/com/copiosa/domain/routine/RoutinePlanner.kt)): every activity carries an arousal weight, activities are sorted descending within bands, high-arousal activity types are hard-excluded from bedtime routines regardless of future library growth, and the session always closes with the lowest-arousal activity (the bedtime story). The learning goal (pre-sleep reactivation) is balanced against the sleep-hygiene goal (don't wind the learner up at bedtime).
- A **serial story** (one continuing narrative per language, with a persisted running summary feeding each night's chapter) adds narrative continuity — recurring characters and vocabulary across nights, which is narrow reading (§2.2) stretched over time and an anticipation hook for routine adherence.

#### 4.3 Learner autonomy and interest-driven content

Self-determination and interest research (and Krashen's "compelling input" refinement) both predict better outcomes when learners control topics. Everything content-shaped in the app is learner-directed: conversations start from any topic, texts are imported from any URL, and the routine draws topics from a table populated by *the learner's own trail* — things they searched, words they looked up, subjects they chatted about, plus model-suggested adjacent topics ([TopicSource.kt](../app/src/main/java/com/copiosa/domain/routine/TopicSource.kt)). Practice content orbits demonstrated interests rather than a fixed syllabus.

### 5. Adaptive difficulty

Vygotsky's zone of proximal development — keep tasks just beyond current ability — and Bloom's mastery learning both argue for difficulty that tracks the individual learner. The routine system implements a compact adaptive engine ([AdaptationMath.kt](../app/src/main/java/com/copiosa/domain/routine/AdaptationMath.kt)):

- Every scored attempt updates a per-bucket **mastery estimate** via exponential moving average, where a bucket is an activity type or, for contrast cloze, an individual contrast category. Response *speed* is part of the signal — fast-correct (≤ 8 s) counts fully, slow-correct partially — treating fluency of access, not just accuracy, as the mastery criterion (automaticity, in skill-acquisition terms).
- Mastery drives two knobs: **difficulty tier** (baseline / harder / hardest content requested from the generator) and **selection weight** (mastered buckets appear more rarely; struggling buckets more often — spending practice time where it buys the most, the same logic FSRS applies to individual cards, at the skill level).
- FSRS itself is the second adaptive layer: per-card difficulty and stability personalize every review interval.

### 6. Methodological infrastructure (meta-level, but load-bearing)

Some engineering choices are themselves methodological commitments:

- **Review history is never lossy.** Full FSRS state and append-only review logs round-trip through Anki `.apkg` import/export, so decades of prior Anki history inform scheduling here, and time invested here is never locked in. (System-of-record is a deliberate "baton hand-off": whichever app currently holds the deck is authoritative.)
- **Everything is measured.** Review logs, per-attempt routine records (correctness + latency), per-bucket proficiency, and per-message generation-settings snapshots (model, level used) mean every pedagogical claim above is empirically checkable against this learner's own data later.
- **The pedagogy degrades gracefully offline.** Scheduling, review, highlighting, translation, and dictionary lookups are fully on-device; LLM-dependent activities drop out of a routine plan and the rest rebalances, rather than the session failing.

## Part 2 — Important concepts NOT yet represented

These are well-supported concepts from SLA research and cognitive psychology that the app does not yet implement, roughly ordered by how much they would matter.

### 2.1 Output and production practice (the biggest gap)

Swain's **Output Hypothesis**: producing language forces syntactic processing, reveals gaps ("noticing the hole"), and builds fluency in ways comprehension alone cannot. The app is currently heavily **input-weighted**. The learner *can* type freely in chat, but nothing in the app requires, scaffolds, or evaluates production:

- No **typed production drills** (type-the-translation, free-response conjugation — both explicitly deferred from the routine library as high-arousal, but also absent from any daytime context).
- No **speaking at all**: no speech recognition, no pronunciation practice, no shadowing or read-aloud, no spoken conversation mode. TTS gives the app a mouth but the learner has no microphone.
- No **writing with feedback**: no journaling/composition flow where the model corrects or reformulates learner text.

A daytime "activation" counterpart to the bedtime routine — built around retrieval-into-production — is the most natural structural fix, since the arousal-gated planner already anticipates high-arousal activity types.

### 2.2 Corrective feedback and negotiation of meaning

Long's **Interaction Hypothesis** locates much of acquisition in the *negotiation* that happens when communication strains — clarification requests, recasts, confirmation checks. The chat currently ignores learner errors entirely: nothing prompts the model to recast an erroneous learner sentence, track recurring error patterns, or gently draw attention to them. The SLA feedback literature (Lyster & Ranta's taxonomy; recasts vs prompts) is directly implementable in the system prompt plus a per-learner error log — high leverage relative to effort, since errors the learner *produces* are the strongest possible signal of what to teach next.

### 2.3 Listening as a trained skill

The app generates audio (playlists, story TTS) but treats listening as passive consumption. Missing: comprehension checks after listening, **dictation/transcription** exercises (a classic integrative task), variable playback with purpose (extensive listening at natural speed vs intensive listening on hard segments), speaker variety, and listening-first presentation of new material (hearing a word before seeing its spelling, which matters for languages with unreliable orthography-phonology mappings — less critical for Spanish, more for future profiles like French).

### 2.4 Frequency-informed vocabulary selection

Nation's cost-benefit principle: the highest-frequency 2,000–3,000 word families cover the vast majority of running text, so *what* you learn matters as much as how you review it. The app schedules whatever the learner happens to save but never advises acquisition order — no frequency-list benchmarking ("you know 70% of the top 1,000 words"), no flagging that a just-saved word is rare (low priority) or that a high-frequency word keeps appearing unlearned in the learner's own texts. The reading pipeline already sees every word the learner reads; cross-referencing against a frequency list would enable "words you keep meeting but haven't saved" — arguably the single most valuable vocabulary feature not yet built.

### 2.5 Fluency development

In Nation's **Four Strands** framework, a quarter of practice time should develop *fluency with known material* — no new language, just faster access. Everything in the app introduces or tests; nothing speeds up. Missing: timed/repeated reading of already-read texts, listening at progressively higher speeds to familiar audio (the speed slider exists but isn't used as a training progression), and 4/3/2-style speaking tasks (blocked on speech support anyway). The response-latency signal in adaptation (§5) measures automaticity but no activity *targets* it.

### 2.6 Pronunciation and phonological training

Beyond speaking practice (2.1): no explicit phonology work at all — minimal-pair discrimination training (perception precedes production), stress/intonation awareness, or grapheme-phoneme regularities. Perception training (high-variability phonetic training) is well-evidenced and needs no microphone — it's a listening MC drill, which the routine infrastructure could host today.

### 2.7 Formulaic language, collocations, and chunks

Usage-based accounts (Ellis; Wray on formulaic sequences) hold that fluent speech is substantially retrieval of prefabricated chunks, not word-by-word assembly. The app has a PHRASE card kind but treats multi-word items as second-class: phrase selections can't get dictionary entries or LLM explanation, nothing surfaces collocational patterns (*tomar* una decisión, not *hacer*), and no activity targets chunk retrieval. Collocation-aware cloze (blank the verb of a verb+noun collocation) would slot directly into the existing cloze machinery.

### 2.8 Pragmatics, register, and sociolinguistic competence

Cards carry region tags and explanations mention register — good seeds — but nothing *teaches* pragmatics: tú/usted navigation, formality switching, speech acts (requesting, apologizing, disagreeing politely), or dialect-specific conventions. Scenario-based chat with a register constraint ("same request, three formality levels") is a cheap LLM-native activity.

### 2.9 Assessment, placement, and self-assessment

The CEFR level is set by hand and never validated. Missing: an initial placement (vocabulary-size tests like a yes/no test are simple and well-studied), periodic can-do self-assessment (the CEFR's own descriptors), and any signal that the learner has outgrown their level. All the data needed to *estimate* level drift already exists (review accuracy, passive-review rates, explanation-request frequency per text) but nothing consumes it.

### 2.10 FSRS parameter personalization

The revlog is faithfully collected and round-trips to Anki, but the app runs FSRS with **default parameters**. The whole point of FSRS's design is per-learner optimization: fitting the 19-ish model weights to the individual's review history measurably improves interval accuracy. With 4,500+ cards and ~48k historical reviews imported, this learner has ample fitting data. (Interim option: let the user paste parameters from Anki's built-in optimizer, since the data round-trips there anyway.)

### 2.11 Interleaving and semantic interference management

Two related sequencing findings with no current representation:

- **Interleaving**: mixing problem/category types within a session beats blocking (Rohrer). Routines partially interleave by construction, but flashcard review sessions are due-date-ordered with no deliberate mixing of card kinds or topics.
- **Interference avoidance**: learning semantically or formally similar items *together* (days of the week, near-synonym sets, *llevar/traer*) creates interference and measurably slows acquisition (Nation's caution against lexical sets). Nothing warns when the learner saves several confusable words the same day, and nothing deliberately separates them in review order.

### 2.12 Multimodal and video input

All input is text or synthesized audio. Video with target-language subtitles — dual-coded, prosodically rich, culturally embedded input — has strong evidence behind it (extensive viewing literature) and dominates how self-directed learners actually spend immersion time. Even without hosting video, the reading pipeline's grading/glossing machinery could apply to user-supplied subtitle files.

### 2.13 Habit scaffolding and goal structure

The absence of streaks, badges, and leaderboards reads as deliberate (consistent with the low-affective-filter stance, and the literature on extrinsic rewards crowding out intrinsic motivation), but lighter-touch, evidence-aligned scaffolding is also absent: implementation intentions ("after I brush my teeth, I do the routine"), a visible daily review commitment sized by FSRS's own due forecast, or gentle load-balancing warnings ("you saved 60 words today; expect a heavy review day in 3 days"). The bedtime routine is itself a habit anchor — the strongest one available — but nothing reinforces the loop around it.
